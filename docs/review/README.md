# 火守 HIMORI 実操作レビューと修正記録

検証日: 2026-11-09。開始時の GitHub main: `16d5a8d5798841701aa04051f608bef6215ed844`。作業ブランチ: `fix/life-records-review`。本番への反映・mainへのマージは行っていません。

## 1. 現行版で分かった良さと問題

「火のある暮らしを育てる。」という言葉が、初焚きの小さな演出、熾火色のカレンダー、棚の写真、樹種との出会い、愛機と過ごした年数まで通っています。薪が減ったことを赤く叱るホームではなく、乾燥薪・乾燥中・来季用をそのまま眺められる点も残しました。空の薪棚から始められ、サンプルは自分で選べる点も良好です。

コミット履歴の初版から現行まで、特に棚管理・ホーム・愛機・カレンダーの再設計、気象V2の仕様記録と修正履歴を読みました。薪割りは「作業の記録」、追加は「棚の量を増やす」、棚チェックは「現在の目視残量を記録する」という既存の役割分担でした。焚いた記録は日記であり、棚の量を自動で減らしません。今回もこの使い方を維持しています。

最優先の問題は、同日チェックの保存確認に入る前に棚の量を書き換えることでした。実操作で **1.8m³ → 20%へ変更 → 保存 → キャンセル** とすると、記録は更新されないのに棚だけ0.4m³になりました。チェック履歴の編集は逆に現在の棚へ反映されず、画面間の数量がずれました。「今日、焚いた」は続けて押すと2件になりました。

バックアップは検証せずキーごとに上書きしていたため、形式違いや保存容量不足による一部だけの復元に弱い実装でした。PWAの旧workerはファイルごとのネットワーク優先で、コメントに書かれた「版が混在しない」という保証を実装では満たしていませんでした。

数量の扱い: 薪割りだけの保存で在庫は増やしません。追加は棚の容量を超える場合、記録を保存せずその場で修正できます。従来のように「記録には全量、棚には一部だけ」という保存をやめました。現在量を測り直した後の過去記録の訂正は、現在の目視量を上書きしません。旧データで削除前の量が分からない場合は、残量を推測せず、現在の量を改めて記録してから履歴を削除する案内を出します。

## 4. テスト環境・結果・限界

macOS、Node.js 24.22.1、Playwright 1.62.1、隔離したChrome 156.0.8078.81。日本時間。390×844（タッチ・モバイル指定）と320×740。普段のブラウザ保存領域・本番のユーザーデータは利用していません。ブラウザ接続ツールは接続不可だったため、自動テスト専用ブラウザを使用しました。

- `tests/data.test.js`: 22件。数量訂正・移動・取消・削除・容量超過・保存失敗・復元失敗時の巻戻し・同日順序・写真参照・JSTの深夜/月末/年末/うるう日・実際の初版コードから作ったバックアップを検証。
- `tests/browser.cjs`: 16チェックポイント。空ホームから棚登録、薪割り単独と棚への追加、同日取消・訂正、連打、初焚き、実画像保存、写真付きデータ往復、再読込/タブ再作成、オフライン、124件、特大文字、エラー確認。
- `tests/edge-browser.cjs`: 写真入力中の重複確認取消、破損JSONのファイル選択、天気取得失敗、年末の最終日集計。
- `tests/pwa.cjs`: v59からv60へ更新。資産1個の失敗では旧workerを維持、入力中の自動再読込なし、ユーザーが更新するまで待機、記録・写真を保持、オフライン再起動/保存、インストール済み同一版から配信。
- 予期しないコンソールエラー・未処理例外: ブラウザ操作テスト0件。意図的な天気取得失敗は既存のcatchで処理。

生の結果: [画面操作](browser-results.json)、[境界条件](edge-results.json)、[PWA更新](pwa-results.json)。テストでは当初、検証コードの文言・閉じるボタンの選択子に不一致があり、実際のUIに合わせて直してから再実行しています。

公開先も読み取り照合しました。38資産中37はmainとバイト一致。`index.html`だけはNetlifyが挿入するホスティング説明コメント3行の差で、アプリのHTMLは一致しました。[ファイル別ハッシュ](public-version.json)。公開サーバー上のアプリコードは開始時mainと同じ版と判断できます。ユーザーのiPhone内のキャッシュは未確認です。

残る確認・制限:

- 実際の薪ストーブユーザーの初見操作、iPhone Safari/ホーム画面版の押しやすさ、カメラ・写真選択・共有/ファイル保存、ピンチ拡大、文字拡大とキーボード、OSによる終了後の再起動は実機確認が必要です。
- 写真は既存どおりlocalStorage保存で容量制限があります。今回のtransactionは同期保存の例外を巻き戻すもので、端末電源断中の原子性や複数タブ同時書込を保証しません。容量不足を模擬したテストは行いましたが、iOS実容量の限界や数千枚の性能は未測定です。
- 通常の再読込/タブ閉じは検証済みですが、未保存入力の再起動をまたぐ自動復元機能は今回追加していません。
- 旧版の写真が端末外URLで保存されている場合、その画像自体のオフライン利用までは保証しません。今回の実画像はdata URLで保存/往復しています。
- 旧版の履歴に重複が既にある場合は勝手に削除しません。新しい「今日、焚いた」の重複を抑止しました。薪割り・メンテの過去記録を一通り編集/削除するUIの拡張は未対応です。
- 既存の気象V2の確認事項・外部APIの利用条件は、仕様記録の保留事項を維持しています。今回は予報値と観測値の意味を変更していません。

## 5. iPhoneでの最終確認（約5分）

修正版のプレビューまたは承認後の公開版で行ってください。現在の公開URLはまだv59です。実際の記録を使う場合は最初に「設定→バックアップを作成」で退避してください。テストは未使用のプレビューURL・テスト用データがおすすめです。

1. **0:00–1:00** 設定の末尾で `v60` を確認。ホームから「第一薪棚」（2m³、50%、乾燥薪）を作り、ホームと棚一覧が1m³になることを見る。
2. **1:00–2:00** 「薪割りを記録」→0.2m³→「続けて、棚に積んだ分を記録」。第一薪棚を選んで保存し、1.2m³を確認。別の薪割りで「作業だけ記録する」を選び、棚の量が増えないことも確認する。
3. **2:00–3:00** 棚チェックを1件保存。残量を変えて再度保存し、確認でキャンセル。量と入力が保持されることを見る。履歴から数量を訂正し、ホーム・棚一覧も一致することを見る。
4. **3:00–4:00** 「今日、焚いた」を続けて2回押す。カレンダーが今日1日の記録となり、初焚きなら節目が出ることを見る。愛機の手入れにiPhoneの実写真を添え、アルバム→この日の記録へ進む。
5. **4:00–5:00** バックアップをファイルへ保存。アプリを閉じ、機内モードで開いて薪割りを記録。文字を特大にして押しやすさ・欠け・写真表示を確認し、通信を戻す。復元確認は、実記録のある本番ではなくテスト用プレビューで同じファイルを取り込む。

更新案内が出たときは入力を保存してから「保存を終えたので更新」を押してください。Safariとホーム画面版の両方を使う場合は、それぞれの保存データ・版表示も確認してください。

## 開発者向けの再実行

Node.jsとGitを用意し、`npm install`、`npx playwright install chromium` の後で `npm test` / `npm run test:browser` / `npm run test:edges` / `npm run test:pwa`。全部と比較撮影は `node tests/run-all.cjs`。既存Chromeを使う場合は `CHROME_PATH`、別のGitは `GIT_PATH` を指定できます。PWAテストは初期main `16d5a8d` の資産を一時フォルダに展開します。

`tests/fixtures/v1-backup.json` は初版 `c56068f` の `seedIfEmpty()` と `exportAllData()` から生成したテストデータで、個人の記録ではありません。
